# Upstream update, 2026-10-08

Updated from Campfire `d2155e85a01b8439c32a3604ebb7f39fea1ace0f` to [`05c5a2c0d72f7fd74d7c2ace23cc123000f956b9`](https://github.com/basecamp/once-campfire/commit/05c5a2c0d72f7fd74d7c2ace23cc123000f956b9), checked against upstream main during this session. The last two commits only update benchmark documentation; the application changes end before `5796e5c`. Rails framework/compiler changes are translated into native Roda/Sequel/Erubi behavior rather than introducing Rails dependencies.

| Upstream change | Roda implementation and evidence |
| --- | --- |
| Header-only browser forgery protection; token-free controls | Fetch Metadata and Origin checks run after method override, with the separately authenticated bot branch preserved. HTTPS writes require a same-origin/same-site fetch header; supplied foreign or null Origins fail. HTTP permits legacy clients with no fetch header. Forms no longer carry CSRF tokens. Inline scripts use exact CSP hashes, avoiding cached nonces. Covered by request-origin, form and CSP tests plus browser posting/transfer flows. |
| Complete-response caching and record snapshots | Bounded process-local cache uses a persistent read-only SQLite `data_version` observer. Commits from every writer invalidate responses and row snapshots. Keys partition viewer, session digest, URL/port, query, cookies, user agent, encoding and Turbo/Accept headers. Authorization precedes reuse; session age is rechecked on every hit. Request-local row copies prevent shared mutation. Transactions, flashes and conditional requests bypass response caching. |
| Message/boost fragments survive unrelated writes | A separate bounded store keys HTML by actual message, room, author, boost and booster values, including microsecond timestamps and request origin. Foreign SQL edits invalidate even without `updated_at` changes. Direct-room names, attachments and embedded attachables stay on the live render path. Tests change bodies, profiles, boosts, room names and request ports. |
| SQLite WAL checkpoints outside requests | One background thread per database wins a file lock and performs passive checkpoints using its own connection. Contenders wait. Shutdown interrupts and joins before forking; workers start independent connections. Tests cover exclusivity, prompt shutdown, committed data and integrity. |
| Atomic messages, FTS and unread state; selective FTS updates | The existing immediate transaction now includes SQLite counter triggers alongside message, index, event, unread and durable-job writes. FTS updates only when stored plain text or primary key changes. Trigger failure rolls the entire operation back in tests. |
| Constant-time bot pagination totals | Migration 005 backfills `rooms.messages_count`; insert/delete/move triggers maintain it, including foreign SQL writers. Bot headers read this counter. Import resets source counters before inserting messages, preventing double counting. Rails-specific database task repair hooks are unnecessary for the native migration/import paths. |
| Avoid rewriting already-unread shared memberships | Shared rooms update only previously read recipients. Direct-room activity still advances. Read/unread events retain fractional timestamps, and the upstream client rejects stale unread notices. The native event reader already performs fanout outside the posting request and rechecks membership before every delivery. |
| Delete large rooms asynchronously | The request removes memberships, closes the room and queues deletion atomically. Existing sockets check authorization before receiving another event. The worker deletes messages in separate transactions before deleting the room. New users cannot join the room while deletion waits. |
| Bounded account member pagination | Administrators are loaded separately; member lists use a 501-row SQL probe for 500-row pages. The same active/banned visibility filter applies on every page. A regression uses more than 500 members. |
| Direct lookup, sidebar and indexed refresh | Canonical indexed direct-room keys and bulk sidebar/participant queries already avoid Rails' old per-room scans. Refresh preserves the indexed room/update-time scan while ordering by creation time; tests find an old message edited after the cursor. Existing room/time indexes are retained without duplicate migrations. |
| Bound unfurling and attachment preview work | A ten-second deadline encloses the entire unfurl, including DNS, redirects and image probes. External media commands also have a ten-second deadline. Thumbnail dimensions are checked before decoding; unreadable uploads remain downloadable. Message views serve existing previews only, and video posters appear only when available. |
| Rich-text files do not trigger preview generation | Import recovers known Active Storage blob metadata from the selected source and signs it locally. Embedded files render their escaped filename/size or caption. Unknown objects still render as missing. A regression ensures rendering never requests a variant. |
| Reuse guarded WebPush TLS connections | The adapted upstream pool keys connections by hostname, port and freshly approved IP, bounds idle sessions and preserves hostname verification. Stale idle connections can be replaced; requests that may have been sent are not retried inside the transport. Response limits/timeouts close the connection. Real local TLS tests cover reuse, address changes, certificate failures, proxy bypass, dropped requests, fork isolation and idle eviction. |
| Push badges and disabled users | Eligible recipients and mentions are gathered once per fanout. Unread counts use one grouped query per subscription batch. Delivery rechecks active membership. Bans retain devices but suppress delivery; deactivation removes them. Empty audiences do not build push payloads. |
| Browser message identity and reconnect fixes | Persisted DOM IDs use database message IDs; client IDs only reconcile pending placeholders. Ported message/read/sidebar/upload controllers preserve same-second read ordering, frame readiness and active direct-message editors. Shared browser and targeted JavaScript regressions cover these behaviors. |
| Ruby/Puma and libvips policy | Production Ruby is 4.0.7 and Puma 8.0.2. YJIT is enabled in production, with `RUBY_YJIT_ENABLE=0` as an opt-out. Direct libvips loader tests prove actual blocked operations, including SVG and OpenSlide. Rails/Herb/RuboCop upgrades do not apply to this runtime. |

`CAMPFIRE_RESPONSE_CACHE_MB` and `CAMPFIRE_FRAGMENT_CACHE_MB` each default to 64 MiB **per worker**, including byte-accounting overhead; individual entries are capped at 1 MiB. Set either to `0` to disable that store. The response budget also contains authorization snapshots. These are payload budgets, not caps on total Ruby RSS. Restart workers after deploying changed templates/assets. The worker must run to process outbound delivery and asynchronous room deletion.

Validation: 134 native tests / 844 assertions on macOS Ruby 4.0.2, and 134 tests / 842 assertions inside the Linux Ruby 4.0.7 production image, with zero failures or errors. The platform skips are unavailable libvips operations: `niftiload` on macOS, and `niftiload`/`dcrawload` on Linux. The shared harness's `bin/check` passes. Shared Chromium flows pass, alongside 136 native HTTP/WebSocket checks and 11 native desktop/mobile Chrome checks. Local TLS tests do not establish delivery through a real push provider, and no automated suite proves every possible input equivalent.
